# 로컬 판정 자원 배포 기록

## 배포 판정

구어체와 받아쓰기 오류 변형을 한국어에만 적용하던 생성기를 영어와 일본어까지
넓힌 뒤 증강 자료로 가중치를 새로 생성해 `VoiceCommand/resources/decision/`에
반영했다. 임계값 0.92와 margin 0.30은 바꾸지 않았다.

아래 수치는 이 기록을 작성하면서 직접 실행한 결과다.

### 시험 파티션 (n=7,217)

| 게이트 | selected | coverage | selective accuracy | false_direct | unknown 오선택 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 없음 | 3,780 | 0.5238 | 1.0000 | 0 | 0 |
| 기존 규칙 | 3,559 | 0.4931 | 1.0000 | 0 | 0 |
| 직접 실행 정책 | 3,556 | 0.4927 | 1.0000 | 0 | 0 |

정확도 0.8182, ECE 0.0524, Brier 0.2438.

언어별 시험 행 수가 한국어 2,748 / 영어 391 / 일본어 412에서
한국어 2,607 / 영어 2,095 / 일본어 2,515로 바뀌었다. 영어와 일본어 시험 자료가
약 5~6배로 늘고 생성 변형을 포함하므로 직전 배포본과 언어별 정확도를 직접
비교할 수 없다. 공정한 비교는 아래 예비 파티션으로 한다.

직전 배포본과 비교하면 전체 정확도가 0.8082에서 0.8182로 0.99%p, 직접 실행 정책
coverage가 0.4647에서 0.4927으로 2.80%p 올랐다. ECE는 0.0470에서 0.0524로
0.0054 나빠졌다. false_direct_count는 모든 게이트에서 0을 유지했다.

### 예비 파티션 (n=369, 언어별 123)

학습에서 격리한 자료이므로 직전 배포본과 같은 조건으로 비교할 수 있다.

| 항목 | 직전 배포본 | 이번 배포본 |
| --- | ---: | ---: |
| 정확도 | 0.5772 | 0.6206 |
| 한국어 | 0.6423 | 0.6504 |
| 영어 | 0.5772 | 0.6585 |
| 일본어 | 0.5122 | 0.5528 |
| 직접 실행 정책 coverage | 0.1301 | 0.1491 |
| 직접 실행 정책 false_direct | 3 | 4 |

세 언어 모두 정확도가 올랐다. 다만 직접 실행 정책 오선택이 3건에서 4건으로
한 건 늘었다.

| 입력 | 정답 | 예측 | confidence |
| --- | --- | --- | ---: |
| `Close the Chrome window` | close_app | focus_window | 0.989 |
| `Open a fresh Chrome window` | launch_app | focus_window | 0.979 |
| `Chromeのウィンドウを閉じて` | close_app | focus_window | 0.998 |
| `크롬을 켜고 유튜브에서 재즈를 찾아 재생해줘` | unknown_or_complex | play_youtube | 0.973 |

앞의 세 건은 모두 같은 원인이다. 영어 학습 자료에서 `window`라는 낱말은
`focus_window`에만 나타나고 `launch_app`과 `close_app`에는 한 건도 없다.
일본어 `ウィンドウ`도 마찬가지다. 그래서 창을 가리키는 낱말이 곧 창 전환
요청이라는 연결이 굳어진다. 증강이 이 낱말이 담긴 행을 112건에서 1,296건으로
늘리면서 `Open a fresh Chrome window`가 임계값을 넘었다.

이 구멍을 씨앗 자료로 메우려고 `launch_app`과 `close_app`에 창을 가리키는
표현 계열을 더해 봤다. 계열이 하나 늘면 `assign_family_splits`의 라운드로빈
위치가 밀려 분할 전체가 바뀌고, 시험 파티션 false_direct_count가 0에서 111건과
118건으로 뛰었다. 예비 파티션 오선택 한 건을 줄이려다 시험 파티션을 크게
망가뜨리는 교환이므로 되돌렸다.

따라서 이 구멍은 분할 안정성을 먼저 고친 뒤에 다뤄야 한다. 예비 파티션은 평가
전용 자료이므로 여기 나온 문장에 맞춘 학습 자료는 넣지 않았다. 네 건 모두
Phase 5에서 인자 해석과 안전 정책을 붙일 때 다뤄야 할 근거로 남긴다.

## 변형 생성기의 언어 대응

기존 생성기는 한국어 외의 입력에 빈 목록을 돌려줬다. 이제 언어별 연산 표를
두고 세 언어를 모두 처리한다. 한국어 표와 알고리즘은 그대로이며, 깨끗한 한국어
문장 983건에 대해 생성 결과가 이전과 완전히 같음을 확인했다.

| 연산 | 한국어 | 영어 | 일본어 |
| --- | --- | --- | --- |
| 조사·관사 생략 | 목적격 조사 | 관사 | 목적격 조사 |
| 어미·요청형 교체 | 존댓말·반말 어미 | 요청 표현 위치 | て형 어미 |
| 목적어·서술어 도치 | 적용 | 해당 없음 | 해당 없음 |
| 머뭇거림 삽입 | 적용 | 적용 | 적용 |
| 말더듬 반복 | 적용 | 적용 | 적용 |
| 받아쓰기 오류 | 적용 | 적용 | 적용 |
| 띄어쓰기 소실 | 적용 | 복합어 결합 | 적용 |
| 과분할 | 적용 | 복합어 분리 | 조사·어간 뒤 공백 |
| 대소문자 변형 | 해당 없음 | 적용 | 해당 없음 |
| 숫자 표기 교체 | 한글 ↔ 숫자 | 영어 ↔ 숫자 | 한자 ↔ 숫자 |
| 문장부호 제거 | 적용 | 적용 | 적용 |

자료 행 수는 16,523에서 35,591로 늘었고 언어 구성은 한국어 12,808 / 일본어
12,334 / 영어 10,449다. 생성 변형이 다른 후보와 같은 문장이 되는 충돌은 0건이다.

## 단계 경계

Phase 1은 정책과 호출 배선 기준으로 완료로 판정한다. 허용 목록, 영구 금지 목록,
`off`·`shadow`·`fast`·`adaptive` 모드와 기본 `shadow` 값이 연결되어 있다.

직접 실행 자체는 Phase 5 경계에 둔다. 현재 판정 결과는 메모리에 보관하고, 인자 해석과
안전 정책 검증이 끝나기 전에는 판정만으로 실행하지 않는다. 따라서 이번 배포는 판정
품질 자료와 판정 자원을 갱신한 것이며 기존 실행 경로의 안전 절차를 우회하지 않는다.

## 검증

다음 명령을 Python 3.11 실행 파일로 수행했다.

```text
py -3.11 -m unittest discover -t . -s tests -p "test_*.py"
```

결과는 `Ran 585 tests in 37.339s`, `OK (skipped=1)`, 종료 코드 0이었다.
`ARI_APP_DATA_DIR`는 임시 경로로 격리했고 검증 후 삭제했다.

구어체와 받아쓰기 오류를 모은 수용 문장 28개로 따로 확인했다. 세 언어 모두
자료에 없는 문장이다.

| 언어 | 통과 | 직전 배포본 |
| --- | ---: | ---: |
| 한국어 | 11 / 11 | 10 / 11 |
| 영어 | 8 / 9 | 8 / 9 |
| 일본어 | 7 / 8 | 6 / 8 |
| 합계 | 26 / 28 | 24 / 28 |

직전 배포본에서 틀리던 `지금 몇시야`와 `音料を上げて`가 통과로 바뀌었다. 남은 두 건은
`Could you open the Chrom window`(focus_window, 0.888)와 `三十分後に教えて`
(get_current_time, 0.390)다. 앞의 것은 위에 적은 `window` 구멍과 같은 원인이고,
둘 다 confidence가 임계값 0.92에 못 미쳐 직접 실행 후보로 뽑히지 않는다.
